# 교안

브라우저로 여는 HTML 네 개입니다. 파일을 더블클릭하면 바로 열립니다.
인터넷 연결이 있으면 글꼴과 코드 색이 함께 적용됩니다.

| 파일 | 내용 | 언제 보나 |
|---|---|---|
| `day1.html` | 0~7단계 · 50장 | 만들면서 |
| `day2.html` | 8~12단계 · 32장 | 만들면서 |
| `day3.html` | 13~22단계 · 38장 | 만들면서 |
| `tour.html` | 완성본을 폴더·파일 순서대로 · 58장 | 만든 뒤, 참고할 때 |

DAY 1·2·3 은 **만드는 순서**입니다. 왜 이게 필요한지를 단계마다 설명하고,
그 단계에서 만드는 파일과 함수를 하나씩 봅니다.

`tour.html` 은 **다 만든 뒤의 모습**입니다. 레일이 단계가 아니라 폴더라서,
"이 함수가 몇 단계였더라" 를 헤매지 않고 파일 위치로 바로 찾습니다.

## 화면 조작

- `←` `→` 키 또는 아래 이전/다음 버튼
- 왼쪽 목록에서 단계·폴더를 눌러 이동
- 코드 블록 오른쪽 위 `복사` 버튼
- 좁은 화면에서는 좌우로 밀어서 넘기기

## tour.html 을 다시 만들려면

`tour.html` 은 손으로 고치지 않습니다. **`tour-src/` 에서 조립합니다.**

```
python docs/tour-src/build_tour.py
```

본문(`t0.html` ~ `t7.html`)에 이렇게 적어두면

```
{{CODE:app/db.py}}     그 파일의 전체 내용이 들어갑니다
{{LINES:app/db.py}}    그 파일이 몇 줄인지 들어갑니다
```

빌드할 때 **`course` 브랜치의 실제 파일 내용**으로 바뀝니다.
코드를 옮겨 적지 않으므로 교안과 코드가 어긋나지 않습니다.

코드를 고친 뒤 이 스크립트를 다시 돌리면 교안이 최신 코드로 갱신됩니다.

### tour-src/ 안에 있는 것

| 파일 | 내용 |
|---|---|
| `tour-head.part` | 스타일과 화면 뼈대 |
| `t0.html` | 프로젝트 지도 · data |
| `t1.html` | pipeline · app 뿌리 3개 |
| `t2.html` | models · schemas |
| `t3.html` | repositories · services · api |
| `t4.html` | ai |
| `t5.html` | rag · tools · graph |
| `t6.html` | tests · eval |
| `t7.html` | web |
| `tour-tail.part` | 이동·복사 스크립트 |

## day1~3 은 어떻게 고치나

이 셋은 조립 스크립트 없이 **HTML 을 직접** 고칩니다.
슬라이드 하나가 `<section class="slide" data-stage="4" data-title="제목">` 한 덩어리입니다.

`data-stage` 가 왼쪽 목록의 단계 번호이고, 같은 번호끼리 이어져 있어야 합니다.

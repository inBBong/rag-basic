실행 부분

DATABASE_URL.startswith("sqlite") 주소를 보고 SQLite 일 때만 옵션을 붙입니다. PostgreSQL 에는 없는 옵션이라 갈라둡니다. 덕분에 Supabase 로 바꿔도 이 파일은 안 고쳐도 됩니다.
check_same_thread: False SQLite 는 원래 만든 스레드에서만 쓰게 되어 있습니다. FastAPI 는 여러 스레드로 요청을 처리해서 이걸 꺼야 합니다.
create_engine(DATABASE_URL, ...) 주소를 보고 어떤 DB 인지 알아서 판단합니다. 이 한 줄 덕분에 나중에 주소만 바꾸면 됩니다.
sessionmaker(bind=engine) "이 통로를 쓰는 세션을 만들어 주는 공장" 을 만듭니다.
declarative_base() 모델들이 물려받을 부모 클래스를 만들어 줍니다. 이 프로젝트는 부모 클래스를 직접 만들지 않지만, 라이브러리가 그렇게 쓰라고 준 것이라 그대로 씁니다.

get_db — 세 줄이 핵심입니다

한 줄씩 뜯어보면
    db = SessionLocal()   # ① 세션을 연다
    try:
        yield db          # ② 넘겨주고 기다린다  ← 여기서 API 함수가 실행됨
    finally:
        db.close()        # ③ 끝나면 반드시 닫는다
yield return 과 달리 함수를 끝내지 않고 값을 잠시 넘겨줍니다. 받아간 쪽의 일이 끝나면 이 줄 다음부터 이어서 실행됩니다.
try / finally 중간에 오류가 나도 finally 는 반드시 실행됩니다. 그래서 세션이 안 닫히는 일이 없습니다.
except 가 없습니다 오류를 잡지 않고 그대로 위로 올려보냅니다. 여기서 삼키면 어디서 뭐가 터졌는지 알 수 없게 됩니다. 우리가 할 일은 "닫는 것" 뿐입니다.
세션이 뭔가요

DB 와 이야기하는 한 번의 대화입니다. 조회하고, 넣고, 저장(commit)하고, 끝나면 닫습니다. 열어두고 안 닫으면 연결이 쌓여서 결국 DB 가 더 못 받습니다.

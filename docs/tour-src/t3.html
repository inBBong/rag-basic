클래스 없이 함수만

class ProductRepository: 를 만들지 않습니다. 인스턴스를 어디서 만들지가 새 고민거리가 됩니다.

첫 인자는 항상 db

함수가 세션을 직접 만들지 않고 받아서 씁니다. 누가 열고 닫을지는 부르는 쪽이 정합니다.

ORM 만, Raw SQL 없음

긴 SQL 문자열을 안 씁니다. 오타를 파이썬이 먼저 잡아주고, DB 를 바꿔도 그대로 돕니다.

돌려주는 모양이 세 가지입니다

객체 목록 find_all → [Customer, Customer, ...]
(객체, 계산값) 짝 find_top_spenders → [(Customer, 596000), ...] 합계액이 컬럼이 아니라 계산값이라 짝이 됩니다.
(객체, 객체) 짝 find_by_customer → [(Purchase, Product), ...] JOIN 으로 두 테이블을 함께 가져온 경우입니다.

스트리밍 쪽 줄별로

def events(): 함수 안의 함수입니다. 바깥 함수의 request 와 history 를 그대로 볼 수 있어서 인자로 넘길 필요가 없습니다.
db = SessionLocal() 여기서만 Depends 를 안 씁니다. Depends 로 받은 세션은 응답을 내보내기 전에 닫히는데, 스트리밍은 내보내는 동안에도 DB 가 필요합니다.
try / finally 중간에 브라우저가 연결을 끊어도 세션이 반드시 닫히게 합니다. get_db 가 하던 일을 손으로 하는 것입니다.
"data: " + json + "\n\n" SSE 형식입니다. data: 로 시작하고 빈 줄 하나로 한 덩어리가 끝납니다.
ensure_ascii=False 한글을 코드가 아니라 글자 그대로 보냅니다.
StreamingResponse(events(), ...) 다 만들어지기 전에 조금씩 내보내는 응답입니다. media_type 이 브라우저에게 "연결을 끊지 말라" 고 알려줍니다.
response_model 이 없습니다 스트리밍은 형식을 미리 정할 수 없습니다. 세 종류가 섞여 나오기 때문입니다.

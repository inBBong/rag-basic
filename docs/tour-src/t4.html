정규식 부분

re.compile(...) 찾을 모양을 미리 만들어 둡니다. 매번 새로 만들지 않아서 빠르고, 다른 파일에서 from app.ai.masking import EMAIL 로 꺼내 쓸 수도 있습니다. 테스트가 실제로 그렇게 씁니다.
r"0\d{1,2}-?\d{3,4}-?\d{4}" 0 으로 시작 → 숫자 1~2개 → 하이픈은 있어도 없어도 됨(-?) → 숫자 3~4개 → 하이픈 → 숫자 4개. 앞의 r 은 역슬래시를 글자 그대로 쓰겠다는 표시입니다.

함수 정의 부분

if not text: return text None 이나 빈 글자면 그냥 돌려줍니다. None 에 정규식을 걸면 오류가 납니다.
EMAIL.sub(hide_email, text) 찾은 것을 바꿉니다. 두 번째가 대상 글, 첫 번째가 바꿀 내용. 함수를 넣으면 찾을 때마다 그 함수를 불러서 나온 값으로 바꿉니다.
PHONE.sub("0**-****-****", ...) 이쪽은 함수가 아니라 고정된 글자로 바꿉니다. 전화번호는 앞자리도 안 남깁니다.
match.group().partition("@") 찾아낸 글자를 @ 기준으로 셋으로 나눕니다: 앞 / 구분자 / 뒤. 가운데는 안 써서 _ 로 받습니다.
f"{name[:2]}***@{domain}" 앞 두 글자만 남깁니다. "eunsu45" → "eu"
dict(chunk, content=mask(...)) 원래 딕셔너리를 복사하면서 한 키만 바꾼 새 딕셔너리를 만듭니다. 원본을 건드리지 않습니다.
isinstance(value, str) 글자인 것만 가립니다. 나이나 가격 같은 숫자에 mask 를 걸면 오류가 납니다.
{key: ... for key, value in row.items()} 딕셔너리를 만드는 짧은 문법. 중괄호를 쓰고 키: 값 으로 적습니다. row.items() 가 (키, 값) 짝을 하나씩 줍니다.
일방향입니다 — 복원하지 않습니다

되돌리는 함수가 없습니다. 그래서 AI 는 진짜 번호를 끝까지 알 수 없습니다. 실제 연락은 관리자가 고객 관리 화면에서 원본을 보고 합니다. 이름과 고객번호는 안 가립니다 — 가리면 "누구인지" 를 답할 수 없습니다.

split_detail — 자르는 규칙

block.startswith("## ") 문서 맨 처음 섹션은 앞에 줄바꿈이 없어서 안 잘립니다. 그 경우만 걸러 앞 3글자를 떼어냅니다.

block.partition("\n") 첫 줄바꿈을 기준으로 셋으로 나눕니다. 앞이 제목, 뒤가 본문. split 이 아닌 이유는 본문 안의 줄바꿈까지 나눠지면 안 되기 때문입니다.

함수 다섯 — 자료를 붙이는 방법

build_history 대화가 없으면 빈 문자열을 돌려줍니다. 그래서 부르는 쪽은 build_history(...) + 질문 이라고만 쓰면 대화가 있든 없든 그대로 동작합니다.
"\n\n".join(...) 조각 사이를 빈 줄로 띄웁니다. 구분이 되어야 AI 가 헷갈리지 않습니다.
f"[{chunk['source_id']}] ..." 조각 앞에 번호를 붙입니다. AI 가 "P001 에 따르면" 처럼 근거를 밝힐 수 있게 됩니다.
build_recommend_prompt 에는 번호가 없습니다 번호를 넣었더니 AI 가 [R0610] 을 상품 이름인 것처럼 답변에 써 버렸습니다. 그래서 추천에서는 본문만 보냅니다.
str(row) build_tool_prompt 는 딕셔너리를 글자로 바꿔 보냅니다. {'name': '오수빈', 'total_spend': 596000} 그대로요. AI 는 이 모양을 잘 읽습니다.

0단계 · 환경 세팅

폴더 열한 개는 세 무리입니다

rag, ai, schemas, models 가 다 같은 층처럼 보이지만 계층은 세 개뿐입니다. 나머지는 계층이 아니라 재료와 부품입니다.

① 요청이 지나가는 길 — 이 셋만 계층입니다

브라우저 ↓ api/ 받습니다 주소와 상태 코드만. 일은 안 합니다. ↓ services/ 시킵니다 업무 로직. 여기가 중심입니다. ↓ repositories/ 꺼냅니다 DB 조회 · 저장. SQLAlchemy 만 씁니다. ↓ DB
규칙 하나 — api 는 repositories 를 직접 부르지 않습니다

아무리 간단한 조회라도 반드시 services 를 거칩니다. 한 번 건너뛰기 시작하면 업무 로직이 두 군데로 갈라집니다.

② 값의 모양 — 계층이 아니라 재료입니다

models/ DB 쪽 모양. 테이블에 어떤 칸이 있는지 적어둔 것입니다. repositories 가 이걸 꺼내 옵니다.
schemas/ 바깥 쪽 모양. 브라우저와 주고받을 값의 형식입니다. 아무것도 부르지 않습니다. 모양만 적어둔 파일이라 그렇습니다.
둘을 나누는 이유

고객 테이블에는 전화번호가 있지만, 화면에 내보낼 값에는 가려진 전화번호가 들어갑니다. DB 모양과 바깥 모양이 달라야 하는 순간이 이렇게 옵니다.

③ AI 부품 — services 가 가져다 씁니다

ai/ OpenAI 호출, 글 자르기, 개인정보 가리기, 벡터 저장·검색
rag/ 검색해서 후보 찾기, 그중 진짜 답 고르기
tools/ AI 가 골라 쓸 수 있는 도구 목록
graph/ 위 부품들을 어떤 순서로 부를지 정한 흐름
이 넷은 층으로 세지 마세요

api → services → ai → rag 처럼 아래로 이어지는 층이 아닙니다. services 옆에 놓인 부품 상자이고, 필요할 때 꺼내 씁니다.

실제 코드의 import 방향

손으로 적은 게 아니라 저장소에서 그대로 뽑은 것입니다.

api → schemas, services services → repositories, models, ai, rag, graph repositories → models ← 여기까지가 요청이 지나가는 길 ai → models rag → ai tools → ai, services graph → ai, rag, tools ← 부품끼리도 서로 씁니다 schemas → (아무것도 부르지 않습니다)
한 줄로 줄이면

services 만 양쪽을 다 부릅니다. 아래로는 repositories, 옆으로는 ai · rag · graph. 그래서 여기가 중심이고, 이 폴더가 서비스 계층입니다.

언제 나오나

2단계 models/ — 테이블 네 개
3단계 api/ · services/ · repositories/ · schemas/ — 계층이 한꺼번에 등장합니다
4~5단계 ai/ — 자르기, 가리기, 임베딩, 벡터 저장
6 · 8단계 rag/ — 검색, 리랭킹
9단계 tools/ — Function Calling 도구
10단계 graph/ — LangGraph 흐름

지금 폴더가 열한 개로 보여도 3단계까지는 다섯 개만 씁니다. 나머지는 필요해지는 단계에서 하나씩 생깁니다.

def write_csv(path, rows, columns):
    # lineterminator 를 "\n" 으로 두면 윈도우와 맥에서 파일이 똑같이 만들어집니다
    with open(path, "w", encoding="utf-8", newline="") as f:
        writer = csv.DictWriter(f, fieldnames=columns, lineterminator="\n")
        writer.writeheader()
        writer.writerows(rows)

def main():
    rows = read_csv(PURCHASES)

    if "review" not in rows[0]:
        print("이미 분리되어 있습니다. 아무것도 하지 않습니다.")

    purchases = [make_purchase(row) for row in rows]
    reviews = [make_review(row, number) for number, row in enumerate(rows, start=1)]

    write_csv(PURCHASES, purchases, PURCHASE_COLUMNS)
    write_csv(REVIEWS, reviews, REVIEW_COLUMNS)


if __name__ == "__main__":

"""
데이터베이스 연결을 담당합니다. 이 파일이 가진 것은 네 가지뿐입니다.

engine        실제 DB 와 연결하는 통로
SessionLocal  DB 작업 한 번에 쓰는 세션을 만들어 주는 공장
Base          모든 테이블 모델이 물려받는 기준
get_db        요청 하나마다 세션을 열고 닫아 주는 함수
"""

from sqlalchemy import create_engine
from sqlalchemy.orm import declarative_base, sessionmaker

from app.config import DATABASE_URL

# SQLite 는 여러 스레드에서 접근할 때 이 옵션이 필요합니다. PostgreSQL 은 필요 없습니다.
# 이렇게 해두면 Supabase 로 옮길 때 이 파일은 고치지 않아도 됩니다.
connect_args = {"check_same_thread": False} if DATABASE_URL.startswith("sqlite") else {}

engine = create_engine(DATABASE_URL, connect_args=connect_args)
SessionLocal = sessionmaker(bind=engine)
Base = declarative_base()


def get_db():
    db = SessionLocal()
    try:
        yield db
    finally:
        db.close()

create_engine(DATABASE_URL) 주소를 보고 어떤 DB 인지 알아서 판단합니다. sqlite:/// 로 시작하면 SQLite, postgresql:// 이면 PostgreSQL. 이 한 줄 덕분에 나중에 주소만 바꾸면 됩니다.
check_same_thread: False SQLite 는 원래 만든 스레드에서만 쓰게 되어 있습니다. FastAPI 는 여러 스레드로 요청을 처리해서 이걸 꺼야 합니다. PostgreSQL 에는 없는 옵션이라 if 로 갈라둡니다.
DATABASE_URL.startswith("sqlite") 주소가 sqlite 로 시작할 때만 그 옵션을 붙입니다. 덕분에 Supabase 로 바꿔도 이 파일은 안 고쳐도 됩니다.
sessionmaker(bind=engine) "이 통로를 쓰는 세션을 만들어 주는 공장" 을 만듭니다. bind 는 어느 engine 에 묶을지입니다.
declarative_base() 모델들이 물려받을 부모 클래스를 만들어 줍니다. 우리가 직접 만든 게 아니라 SQLAlchemy 가 만들어 준 것이라 그대로 씁니다.

열어두고 안 닫으면 연결이 쌓여서 결국 DB 가 더 못 받습니다. 그래서 get_db 가 필요합니다.

이 세 줄이 핵심입니다
    db = SessionLocal()   # ① 세션을 연다
    try:
        yield db          # ② 넘겨주고 기다린다  ← 여기서 API 함수가 실행됨
    finally:
        db.close()        # ③ 끝나면 반드시 닫는다
yield return 과 달리 함수를 끝내지 않고 값을 잠시 넘겨줍니다. 받아간 쪽의 일이 끝나면 이 줄 다음부터 이어서 실행됩니다.
try / finally 중간에 오류가 나도 finally 는 반드시 실행됩니다. 그래서 세션이 안 닫히는 일이 없습니다.
except 가 없습니다 오류를 잡지 않고 그대로 위로 올려보냅니다. 여기서 삼키면 어디서 뭐가 터졌는지 알 수 없게 됩니다. 우리가 할 일은 "닫는 것" 뿐입니다.

DATA = Path(__file__).parent.parent / "data"


def read_csv(name):
    with open(DATA / name, encoding="utf-8", newline="") as f:
        return list(csv.DictReader(f))


def make_customer(row):
    return Customer(
        customer_id=row["customer_id"],
        name=row["name"],
        gender=row["gender"],
        age=int(row["age"]),

api/ 요청을 받고 응답을 돌려줍니다. HTTP 를 아는 유일한 층입니다. DB 를 직접 만지지 않습니다.
services/ 업무 로직입니다. 지금은 얇지만 나중에 여러 단계를 묶는 자리가 됩니다.
repositories/ DB 에 접근합니다. db.query(...) 는 여기서만 씁니다. 쿼리를 고칠 일이 있으면 이 폴더만 보면 됩니다.
schemas/ 주고받는 JSON 의 형식입니다. 계층은 아니고, 모양을 정하는 곳입니다.
Repository 는 클래스 없이 함수만 씁니다

class ProductRepository: 를 만들지 않습니다. 함수 하나에 첫 인자는 항상 db 로 통일합니다.

"""

import re

PHONE = re.compile(r"0\d{1,2}-?\d{3,4}-?\d{4}")


def hide_email(match):
    """eunsu45@example.com  ->  eu***@example.com"""
    name, _, domain = match.group().partition("@")
    return f"{name[:2]}***@{domain}"


def mask(text):
    if not text:
        return text

    text = EMAIL.sub(hide_email, text)
    text = PHONE.sub("0**-****-****", text)
    return text


def mask_chunks(chunks):
    """검색해 온 청크들의 본문을 가립니다."""
    return [dict(chunk, content=mask(chunk["content"])) for chunk in chunks]


def mask_rows(rows):
    """도구가 DB 에서 가져온 결과를 가립니다.

    고객 조회 결과에는 전화번호와 이메일이 그대로 들어있습니다.
    글자로 된 값만 가리고 숫자는 그대로 둡니다.
    """
    return [
        {key: mask(value) if isinstance(value, str) else value for key, value in row.items()}
        for row in rows
    ]

"""

import re

EMAIL = re.compile(r"[\w.+-]+@[\w-]+\.[\w.]+")
PHONE = re.compile(r"0\d{1,2}-?\d{3,4}-?\d{4}")


def hide_email(match):
    """eunsu45@example.com  ->  eu***@example.com"""
    name, _, domain = match.group().partition("@")
    return f"{name[:2]}***@{domain}"


def mask(text):
    if not text:
        return text

    text = EMAIL.sub(hide_email, text)
    text = PHONE.sub("0**-****-****", text)
    return text


def mask_chunks(chunks):
    """검색해 온 청크들의 본문을 가립니다."""
    return [dict(chunk, content=mask(chunk["content"])) for chunk in chunks]


def mask_rows(rows):
    """도구가 DB 에서 가져온 결과를 가립니다.

    고객 조회 결과에는 전화번호와 이메일이 그대로 들어있습니다.
    글자로 된 값만 가리고 숫자는 그대로 둡니다.
    """
    return [
        {key: mask(value) if isinstance(value, str) else value for key, value in row.items()}
        for row in rows
    ]

    DB 가 아니라 원본 CSV 를 읽습니다. 청크는 저장하기 전에 이미 가려서

    with open("data/reviews.csv", encoding="utf-8") as f:

"""

chunks 테이블을 다루는 곳은 이 파일 하나뿐입니다. (pipeline 스크립트만 예외)
SQLite 와 Supabase 의 차이를 전부 이 파일 안에 가둬 두려는 것입니다.
마지막에 Supabase 로 옮길 때 고치는 파일이 여기 하나로 끝납니다.

지금은 SQLite 라서 벡터를 JSON 문자열로 저장합니다.
"""

import json

from app.models.chunk import Chunk


def find_chunks_to_embed(db):
    """아직 벡터가 없는 청크만 가져옵니다.

    이 함수 덕분에 나중에 증분 임베딩이 가능합니다.
    새 상품을 추가해도 그 상품의 청크만 벡터가 없으니, 그것만 임베딩하면 됩니다.
    """
    # SQLAlchemy 에서 "값이 비어 있다" 는 is None 이 아니라 is_(None) 으로 씁니다.
    return db.query(Chunk).filter(Chunk.embedding.is_(None)).all()


def save_embeddings(db, chunks, vectors):
    """청크에 벡터를 붙여 저장합니다."""
    for chunk, vector in zip(chunks, vectors):
        chunk.embedding = json.dumps(vector)
    db.commit()


def count_all(db):
    return db.query(Chunk).count()


def count_embedded(db):
    return db.query(Chunk).filter(Chunk.embedding.is_not(None)).count()


def find_first_embedded(db):
    """벡터가 어떻게 생겼는지 확인해 볼 때 씁니다."""
    return db.query(Chunk).filter(Chunk.embedding.is_not(None)).first()

def search(db, query_vector, top_k=10):
    """질문 벡터와 뜻이 가까운 청크를 top_k 개 찾아옵니다."""
    if _vectors is None:
        load_into_memory(db)

    # 벡터들의 길이가 모두 1이라서, 곱해서 더하기만 하면 그게 곧 코사인 유사도입니다.
    # 1에 가까울수록 뜻이 비슷하고, 0에 가까울수록 상관이 없습니다.
    scores = _vectors @ np.array(query_vector, dtype=np.float32)

    best = np.argsort(-scores)[:top_k]
    return [dict(_chunks[index], score=float(scores[index])) for index in best]

    return db.query(Chunk).count()


def count_embedded(db):
    return db.query(Chunk).filter(Chunk.embedding.is_not(None)).count()


def find_first_embedded(db):
    """벡터가 어떻게 생겼는지 확인해 볼 때 씁니다."""
    return db.query(Chunk).filter(Chunk.embedding.is_not(None)).first()


def load_into_memory(db):
    """DB 의 벡터를 전부 읽어서 메모리에 올립니다. 처음 한 번만 실행됩니다."""
    global _chunks, _vectors

    rows = db.query(Chunk).filter(Chunk.embedding.is_not(None)).all()

    # DB 객체를 그대로 들고 있으면 세션이 닫힌 뒤에 쓸 수 없습니다.
    # 그래서 필요한 값만 뽑아서 보통 딕셔너리로 담아둡니다.
    _chunks = [
        {
            "chunk_id": row.chunk_id,
            "source": row.source,
            "source_id": row.source_id,
            "product_id": row.product_id,
            "section": row.section,
            "content": row.content,
        }
        for row in rows
    ]
    _vectors = np.array([json.loads(row.embedding) for row in rows], dtype=np.float32)


def search(db, query_vector, top_k=10):
    """질문 벡터와 뜻이 가까운 청크를 top_k 개 찾아옵니다."""
    if _vectors is None:
        load_into_memory(db)

    # 벡터들의 길이가 모두 1이라서, 곱해서 더하기만 하면 그게 곧 코사인 유사도입니다.
    # 1에 가까울수록 뜻이 비슷하고, 0에 가까울수록 상관이 없습니다.
    scores = _vectors @ np.array(query_vector, dtype=np.float32)

    best = np.argsort(-scores)[:top_k]
    return [dict(_chunks[index], score=float(scores[index])) for index in best]

RAG_SYSTEM = """당신은 화장품 쇼핑몰의 상담 담당자입니다.

지켜야 할 것
- 아래 참고 자료에 있는 내용만으로 답합니다.
- 자료에 없는 내용은 지어내지 말고 "자료에서 확인되지 않습니다" 라고 답합니다.

    return f"""참고 자료
{context}

질문
{question}"""

"""
AI 에게 질문하고 답을 만듭니다. 이게 RAG 의 전부입니다.

  1. 질문과 비슷한 글을 찾는다        (Retrieval)
  2. 찾은 글을 참고 자료로 붙인다      (Augmented)
  3. AI 에게 답을 만들게 한다          (Generation)
"""

from app.ai import llm, prompts
from app.rag.retriever import retrieve


def ask(db, question):
    chunks = retrieve(db, question)

    user_prompt = prompts.build_rag_prompt(question, chunks)
    answer = llm.ask(prompts.RAG_SYSTEM, user_prompt)

    return {"question": question, "answer": answer, "sources": chunks}

"""
AI 에게 보낼 문장을 모아둡니다.

프롬프트를 코드 여기저기에 흩어 두면 나중에 고칠 때 찾기 어렵습니다.
그래서 한 파일에 모읍니다.
"""

RAG_SYSTEM = """당신은 화장품 쇼핑몰의 상담 담당자입니다.

지켜야 할 것
- 아래 참고 자료에 있는 내용만으로 답합니다.
- 자료에 없는 내용은 지어내지 말고 "자료에서 확인되지 않습니다" 라고 답합니다.
- 한국어로, 세 문장 이내로 짧게 답합니다.
- 다음에 무엇을 더 해줄지 먼저 제안하지 않습니다. 물어본 것에만 답합니다."""


def build_rag_prompt(question, chunks):
    """검색해 온 청크를 참고 자료로 붙여서 질문 문장을 만듭니다."""
    context = "\n\n".join(f"[{chunk['source_id']}] {chunk['content']}" for chunk in chunks)

    return f"""참고 자료
{context}

질문
{question}"""

"""AI 질문과 답변의 형식입니다."""

from pydantic import BaseModel


class AskRequest(BaseModel):
    question: str


class SourceOut(BaseModel):

    source_id: str
    product_id: str
    section: str | None
    score: float
    content: str

    question: str

"""
AI 에게 질문하고 답을 만듭니다. 이게 RAG 의 전부입니다.

  1. 질문과 비슷한 글을 찾는다        (Retrieval)
  2. 찾은 글을 참고 자료로 붙인다      (Augmented)
  3. AI 에게 답을 만들게 한다          (Generation)
"""

from app.ai import llm, prompts
from app.rag.retriever import retrieve


def ask(db, question):
    chunks = retrieve(db, question)

    user_prompt = prompts.build_rag_prompt(question, chunks)
    answer = llm.ask(prompts.RAG_SYSTEM, user_prompt)

    return {"question": question, "answer": answer, "sources": chunks}
